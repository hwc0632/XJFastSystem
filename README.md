## 1. 软件简介

玄景遥感快速处理软件（简称 **XJFastSystem**）是武汉玄景科技有限公司针对航天与遥感客户推出的常用遥感处理算法集合，**无交互式编辑功能**，以"参数智能配置 + 流程自动化"为设计目标，降低遥感处理算法的使用门槛。

软件覆盖从**原始码流到 L4 级基础遥感产品**的完整链路：

| 环节 | 能力 |
| --- | --- |
| 数据接收 | 快视、回放显示 |
| 数据解析 | 帧同步、解扰、信道解码、解帧、解压格式化、编目、物理分景、浏览图、云判、辅助数据分离 → L0 |
| 影像预处理 | 相对辐射校正、光谱复原、传感器校正、波段配准、MTFC、RFM 模型生成 → L1 |
| 多级产品生产 | 系统几何校正、几何精校正、正射校正、绝对辐射校正、大气校正、反射率反演 → L2/L3/L4 |
| 后处理 | DSM 生产、匀光镶嵌、快速融合、快速超分重建 |
| 快速处理 | 快速传感器校正、快速地理配准（应急处理，不依赖星上辅助数据与定标信息） |
| 通用支撑 | EOP 地球定向参数更新 |

当前的 **V1.0 为简易单机试用版本**，后期将根据用户反馈修复问题并随需求变化适当扩充。完整版本不提供试用。

## 3. 运行环境与授权

- **平台**：Windows x64 单机版
- **依赖**：软件目录已内置 GDAL、PROJ9、OpenCV、ONNX Runtime、CUDA Runtime 等运行库，**无需额外安装**，但请勿拆分目录或单独移动 exe/dll。
- **硬件加速**：
  - DSM 密集匹配支持 `SGM_CUDA` / `SGM_GLSL` / `SGM_AVX2` / `SGM_SSE` 四种加速方式；使用 `SGM_CUDA` 需具备 NVIDIA 显卡且驱动更新到最新。
  - 快速超分重建依赖 `model\` 下的 ONNX 模型（RealESRGAN、SwinIR 等），可采用 GPU 或 CPU 推理。
- **网络**：
  - 试用版**需要保持网络畅通**以完成联网试用验证，单机每天允许试用 10~20 次不等（视不同功能模块）。
  - 多级产品生产、DSM 生产、匀光镶嵌、快速地理配准等模块可使用**在线网络控制信息/参考底图**（Online Control Source / WMS），需要网络与代理支持。
  - 内网或无网环境支持**单机激活**，需联系公司获取单机试用激活码。
- **EOP 参数**：影像预处理与几何检校需要在线地球定位定向参数文件 `EOP00.txt`，软件目录已内置一份，可通过 **EOP 参数更新软件** 联网更新。

## 5. 快速开始

1. **启动总入口**
   双击 `XJFastSystem.exe`，打开玄景遥感快速调度软件。界面按"预处理 / 后处理 / 快速处理"三类列出全部功能模块。

2. **必要的初始化**
   - 首次使用建议先运行 **EOP 参数更新软件**：`星历下载` → `格式转化`，生成/更新 `XJFastSystem\EOP00.txt`。
   - 若为内网/无网环境，先完成单机激活。

3. **按链路依次处理（以 XJ01 测试数据为例）**
   ```
   KS_XJ01_20260820_231200.dat
        │  数据解析 (GeoParseUI)          → L0 产品（影像 + EPH/ATT/IT/元数据等）
        ▼
   L0\...\KS_XJ01_20260820_231200_001_L0_MUX.tif / _PAN.tif
        │  影像预处理 (PreProcessUI)       → L1 产品（L1A/L1B，融合为 L1BF）
        ▼
   L1\...\XJ01_..._L1BF_PSH.tif
        │  多级产品生产 (LevelProcessUI)   → L2A/L2B/L3A/L3B/L4A/L4B
        ▼
   L2/L3/L4 产品
   ```
   后处理（DSM、匀光镶嵌、融合、超分）与快速处理（快速传感器校正、快速地理配准）为独立支线，可单独使用。

4. **语言切换**
   各模块均支持中英文切换，且**统一受快速调度软件单向联动控制**（在调度软件中切换即可）。

5. **关于对话框**
   各模块右上角 `?` 按钮可查看软件版本与其他信息。

## 6. 遥感产品分级体系

参考国内外各类遥感卫星标准产品体系并结合国产卫星特点，武汉玄景科技有限公司的遥感卫星标准产品体系如下：

| 级别 | 说明 |
| --- | --- |
| 原始数据 | 地面接收到的星上下传的原始码流数据 |
| **L0** | 进行帧同步、解扰、信道解码、解帧、解析解压格式化、编目、物理分景、浏览图生成、云判和辅助数据分离，并匹配完整的处理与应用辅助数据后生成的**分景原始数据产品** |
| **L1A** | 在 L0 基础上增加相对辐射校正、传感器拼接、波段配准、(MTFC)、RPC 文件生成等，生成的 **DN 值分景影像产品**（MTFC 为可选项）。干涉型高光谱成像仪则增加相对辐射校正、光谱复原、传感器校正、谱段配准、RPC 生成 |
| **L1B** | 产品描述文件中包含**绝对辐射定标系数**，用于后续入瞳处辐亮度计算。高光谱数据在 L1A 基础上增加光谱校正 |
| **L2A** | 在 L1A 基础上增加**系统几何校正**，生成 DN 值分景影像产品 |
| **L2B** | 在 L2A 基础上增加**绝对辐射校正**，生成分景辐亮度产品 |
| **L3A** | 在 L1A 基础上增加**几何精校正**，生成 DN 值分景影像产品 |
| **L3B** | 在 L3A 基础上增加**绝对辐射校正**，生成分景辐亮度产品 |
| **L3C** | 在 L3B 基础上增加**大气校正、地表反射率计算**，生成分景地表反射率产品 |
| **L4A** | 在 L1A 基础上增加**正射校正**，生成 DN 值分景影像产品 |
| **L4B** | 在 L4A 基础上增加**绝对辐射校正**，生成分景辐亮度产品 |
| **L4C** | 在 L4B 基础上增加**大气校正、地表反射率计算**，生成分景地表反射率产品 |

> **融合影像特殊标记**：融合处理后的影像载荷标记变为 `PSH`，产品级别后增加 `F` 标记（如 `L1B` → `L1BF`），其他级别不加 F。

## 7. 模块使用说明

### 7.1 数据快视软件（`QuickLookUI.exe`）

对星上原始数传数据进行实时或回放显示，包括帧同步、解扰、信道解码、解帧、解析解压格式化等操作，并支持保存当前快视图。**需针对不同载荷平台接口协议定制适配**，测试数据提供 MODIS 载荷协议。

**数据导入与播停**

- 数据来源分**实时模式**与**回放模式**；当前试用版仅支持 MODIS 回放模式从本地导入。
- 数据导入：先选择卫星 `Aqua(MODIS)`，点击 `打开文件…` 选择 dat 文件。
- 播放 / 暂停 / 停止：播放时显示窗口流式显示快视影像，右侧信息窗口持续更新帧解析信息与速率信息。

**显示与速率设置**

| 设置项 | 说明 |
| --- | --- |
| 波段选择 | 切换波段时新快视图**接着原图后面写**，不刷新；选择 `彩色(RGB)` 时原快视图被清空（MODIS 的 RGB 组合为 1/4/3） |
| 缩放选择 | 下拉框选择缩放级别，或点击 `+` / `-` 逐级缩放 |
| 方向选择 | `向上(下→上)` / `向下(上→下)` 控制滚动方向 |
| 速率选择 | 默认 **300 Mbps**；设置过大时软件会按实际硬件情况酌情降速 |
| 全屏显示 | 双击显示窗口进入全屏，再次双击或按 `ESC` 退出 |

**保存图像**：点击 `保存图像…`，默认文件名与 Dat 数据同名，支持 `tif / png / bmp / jpg` 四种格式。

**其他**：语言切换（受调度软件控制）、关于对话框。

---

### 7.2 数据解析软件（`GeoParseUI.exe` / `GeoParse.exe`）

对星上原始数传数据进行帧同步、解扰、信道解码、解帧、解析解压格式化、编目、物理分景、浏览图生成、云判和辅助数据分离，并匹配完整的处理与应用辅助数据，生成**分景原始 L0 级数据产品**。需按载荷平台接口协议定制适配，测试数据为 XJ01 平台。

**输入**：地面数据接收站接收的星上原始下传数据，后缀为 `dat`。

**界面参数（GeoParseUI）**

| 参数 | 说明 |
| --- | --- |
| 平台选择 | **必须**与输入 dat 对应，决定解析算法 |
| Key 编号 | 部分平台载荷存在数据加密 Key；测试数据无需 Key，默认灰显 |
| 仅解析辅助数据 | 只输出辅助数据不输出影像；辅助数据位于载荷帧中，**勾选并不能跳过 AOS 帧解译**。推荐默认不勾选 |
| 覆盖之前的结果 | 不勾选时自动检查文件完整性、跳过已解译过程以提高效率。**推荐默认勾选** |
| 删除中间文件 | 结束后自动删除中间文件夹（如 `..._RAW`）。**推荐默认不勾选**，便于查看 |
| RAW | 部分 Dat 为 RAW 格式但协议无标注时需人工提示；测试数据无此问题，默认置灰 |
| Dat 文件路径 | 输入 dat 文件；若完全遵循命名规范，选取后软件**自动完成平台选择**，并在中间/结果路径为空时自动设为 Dat 所在文件夹 |
| 中间文件路径 | 存储中间输出文件，如生成 `KS_XJ01_20260820_231200_RAW` 文件夹 |
| 结果文件路径 | 存储输出结果；单相机载荷生成 `..._L0` 文件夹；多相机异步工作时按任务分别生成（如 `..._001_L0_PMS`） |

批处理操作：`添加` / `批量添加` / `删除` / `清空` / `运行` / `退出`。
**运行规则**：批处理格网有记录时逐项依次运行，每项完成后自动关闭控制台信息并在 `COM` 列打 √；格网为空时仅按界面参数运行，任务完成后不关闭控制台。

| 字段 | 含义 |
| --- | --- |

| `RawFileName` | 星上原始数传数据路径 |

### 7.3 影像预处理软件（`PreProcessUI.exe` / `PreProcess.exe`）

对分景原始 L0 级数据产品进行相对辐射校正、(光谱复原)、传感器校正、波段配准、(MTFC)、RFM 模型生成等处理，生成 **DN 值表示的分景 L1 级数据产品**。采用**完全严格的几何与物理模型**，需使用离线定标得到的几何、辐射和物理参数。需按平台与载荷定制适配（主要是定标与处理参数配置），测试数据提供 XJ01 处理流程。

**界面处理流程**

| 流程 | 说明 |
| --- | --- |
| 标准处理流程 | 对选中的单个载荷文件进行单载荷处理，**不勾选"联合处理"** |
| 联合处理流程（线阵+线阵） | 勾选"联合处理"，多个线阵载荷进行联合编目后再做 L1 生产；若配置了全色/多光谱载荷则进行融合 |
| 联合处理流程（线阵+滑动面阵） | 当前测试数据不包含，略 |
| 面转线处理流程 | 当前测试数据不包含，略 |

**主要界面参数**

| 参数 | 说明 |
| --- | --- |
| 平台与载荷选择 | 影像路径遵循 L0 命名规范时会**自动填充** |
| 重采方法 | 默认 `BiCubic_4P` |
| 数据精化 | 利用影像内容修复辅助数据质量，较慢且可能使高质量数据变差。**推荐默认不勾选** |
| 分景编目 | 勾选则按标准景及编目格网切景；不勾选则按超景方式生产全条带 L1 产品。**推荐默认勾选** |
| 辐射校正 | 勾选则进行相对辐射校正（条纹去除）；若存在绝对辐射参数、光谱定标参数，将随 L1 元数据输出。不勾选则不做任何辐射与光谱处理，相应参数也不写入元数据 |
| MTFC | 勾选且存在 MTF 文件时进行 MTF 补偿 |
| 传感器校正 | **L1 产品生产的核心步骤，建议务必勾选** |
| 联合处理 | 标准流程**应不勾选**；联合流程下可勾选"多光谱升采样"（会明显变慢） |
| 采用格网及大小 | 传感器校正的算法加速手段，保证精度前提下提高多倍效率 |
| 采用 DEM | 对高分辨率与大角度数据，避免投影差影响谱段配准与 CCD 拼接精度 |
| 范围裁剪 | 裁剪机械拼接影像首尾多余部分，保证结果规整 |
| 多光谱升采样 | 用于对比全色与多光谱 L1 产品的像素级配准，通常不勾选 |
| 影像路径 / DEM 路径 / Geoid 路径 / 输出文件夹 | DEM 与 Geoid 已内置默认路径，可在打开程序时自动填写；SRTM 以 EGM96 正高为基准 |

**后台作业模式（`SCInput.xml`）**

`<Process>` 支持：自动化全流程 `ALL`、数据优化 `AP`、数据编目 `CA`、物理分景 `DX`、辐射校正 `RC`、MTF 补偿 `MTFC`、传感器校正 `SC`、影像融合 `Fusion`。

| 字段 | 含义与作用范围 |
| --- | --- |
| `Platform` | 平台类型，**必须写对**，否则找不到配置/定标参数，程序无法执行或崩溃 |
| `ResampleType` | 重采样方法，支持 `Nearest_Neighbor_1P`、`Bilinear_2P`、`BiCubic_4P`、`BiCubic_6P`、`BSpline_4P`、`Lanczos_4P`、`Lanczos_6P`、`KnabSW_4P`、`KnabSW_6P`、`RasiedCosine_4P`、`RasiedCosine_6P`，建议 `BiCubic_4P` |
| `Camera` | 处理载荷名称，**必须与 ImgPath 所选影像载荷对应** |
| `receiveID` | 接收站名称，仅用于传递元数据 |
| `ImgPath` | 待处理 L0 级条带/影像 |
| `DemPath` / `GeoidPath` | 全球 SRTM / EGM96 大地水准面路径 |
| `OutFolder` | 输出文件夹路径 |
| `Process` | 处理步骤（见上） |
| `isAP` | 是否数据优化，只对整条带作用，仅对 `ALL`/`AP` 有效 |
| `isDX` | `0` 超景生产，`1` 标准景生产，仅对 `ALL`/`CA` 有效 |
| `isRC` | 是否辐射校正（含相对辐射校正、绝对辐射校正、贝尔插值、盲元校正、光谱校正），仅对 `ALL`/`RC` 有效 |
| `isMTFC` | 是否 MTFC，仅对 `ALL`/`MTFC` 有效 |
| `isSC` | 是否传感器校正，仅对 `ALL`/`SC` 有效 |
| `isUnion` | 是否联合操作/P2L 操作：`0` 独立编目独立处理；`1` 联合编目联合处理。**仅联合处理时才可能触发 Fusion**（是否融合取决于 `UP.ini`）。`UP.ini` 无联合载荷时此选项不起作用 |
| `isGrid` / `GridSize` | SC 是否采用加速格网及格网大小（默认 24），仅对 `SC` 有效 |
| `isDEM` | SC 是否采用全球 SRTM，仅对 `SC` 有效 |
| `isCut` | SC 是否裁剪上下错位部分，对机械拼接相机生成标准景较重要，仅对 `SC` 有效 |
| `isUpRes` | 联合操作时多光谱是否上采样至与全色配准，仅对 `SC` 有效 |
| `IsDelTmp` / `IsDelAP` | 是否删除 RGB/RC/MTFC 等临时文件 / ap 和 nc 临时文件 |
| `StartLine` / `EndLine` | 分景起止行，仅对手动流程 `DX` 且 SceneID 不在编目文件中时有效 |
| `SceneID` | 在 `ALL`/`CA` 中表示编目逻辑分景起始景 ID；在 `DX` 中表示物理分景景 ID |
| `IsPause` | 完成后是否暂停 |

**流程要点**

- **自动化流程（`Process=ALL`）**：只进行逻辑分景，生成与 tif 同名的编目 xml，不做物理分景。AP/RGB/RC/MTFC 直接对整个条带进行，随后 SC 才切景，可大幅节省时间与空间。`SceneID` 表示编目起始号码，`StartLine`/`EndLine` 无效。
- **分步流程（`Process=AP/CA/DX/RC/SC/Fusion`）**：`AP` 对整条带进行；`CA` 为独立编目流程（只做逻辑分景，生成编目文件夹与每景缩略图）；`DX` 为物理分景流程，各景之间可独立并发进行，适合业务系统并发调度；独立流程中 RGB/RC/MTFC 是对物理分景后的单景进行。
- 配置文件可通过 `PreProcess.ini` 中的 `PRE_CONFIG` 字段指定绝对路径（默认 `PreConfig` 文件夹）。

**输出**：L1 级产品；联合处理融合输出的载荷标记为 `PSH`，级别加 `F`（如 `L1BF`）。

### 7.4 多级产品生产软件（`LevelProcessUI.exe` / `LevelProcess.exe`）

在 L1 基础上进行系统几何校正、精校正、正射校正、绝对辐射校正、大气校正、反射率反演等处理，得到 L2/L3/L4 级基础遥感产品。几何校正**既可本地控制，也支持在线网络控制**。

**两种处理模式**

| 模式 | 输入 | 输出 |
| --- | --- | --- |
| **定制处理模式** | 影像预处理输出的 L1 产品（遵循 L1 命名规范，自动识别） | 完整附带元数据、地理信息、缩略图等配套信息 |
| **通用处理模式** | 带 RFM 模型的遥感影像（`RPC` 或 `RPB` 格式） | 仅输出带地理编码格式的影像，不产生元数据文件 |

**产品级别与处理模式支持对照**

| 产品级别 | 定制处理模式 | 通用处理模式 |
| --- | :-: | :-: |
| L2A / L3A / L4A | ✔ | ✔ |
| L2B / L3B / L4B | ✔ | ❌ |
| L2C / L3C / L4C | ❌ | ❌ |

> 当前软件对自动大气校正和反射率反演支持较弱，**暂不支持 L3C/L4C 生成**；绝对辐射校正**仅支持定制处理模式**。未来将利用网络控制信息和大气信息实现自动计算。

**主要界面参数**

- **影像路径**：遵循 L1 命名规范时自动识别为定制处理模式并搜索元数据。
- **控制点路径**：几何精纠正与正射纠正使用，格式见附录十控制数据格式；支持本地文件或 `Online Control Source` 网络获取。**仅对 L3/L4 级有效**。
- **DEM 路径**：正射校正使用，支持本地或网络（正高系统）；**仅对 L4 级有效**。
- **Geoid 路径**：DEM 为正高系统时用于转换为椭球高；**仅对 L4 级有效**。
- **生产级别**：按上表选取。
- **投影设置**：仅支持 `WGS84` 与 `WGS84_UTM`（6° UTM 投影，投影带自动计算）。
- **重采方法**：默认 `BiCubic_4P`。
- 批处理支持**批量添加**（选择文件夹后自动搜索所有满足格式要求的影像）。

**后台作业模式（`GECInput.xml`）**

| 字段 | 含义 |
| --- | --- |
| `ImgPath` | 待处理 L1 级影像 |
| `GCPPath` | 控制点文件路径，或 `Online Control Source` |
| `DEMPath` / `GeoidPath` | 高程数据 / 全球大地水准面路径 |
| `OutFolder` | 输出文件夹路径 |
| `FunType` | 分级处理级别：`L2A/L2B/L3A/L3B/L3C/L4A/L4B/L4C` |
| `ProjType` | 输出投影：`WGS84` 或 `WGS84_UTM` |
| `ResampleType` | 重采样方法（同 7.3） |
| `strHostName` / `strPort` | 代理 IP 与端口 |
| `IsPause` | 完成后是否暂停 |

**输出**：L2/L3/L4 级产品；通用模式输出文件夹及影像名称为 `原始影像名称_产品级别`。

### 7.7 数字表面模型(DSM)生产软件（`SurfProcessUI.exe` / `SurfProcess.exe`）

对带有 RFM 模型的 L1 级遥感立体像对进行 (带控)立体平差、核线纠正、密集匹配、DSM 插值等操作，得到 DSM。目前**仅支持 tSGM 算法**，兼容 Cuda、GLSL、AVX2、SSE 四种加速方法。

> ⚠️ 该软件带控立体平差的控制信息**仅支持在线网络控制**，精度比较有限，**建议用户不启用此功能**，输入数据采用用户自己平差后的数据。

**输入**：带 RFM 模型的 L1 级立体像对。测试数据包含 GF7 两组立体像对、Pleiades 一组三视像对、ZY303 四组三视像对（提供 12.5 m 格网参考 DEM 供对比），**均未进行立体平差**。

**主要界面参数**

| 参数 | 说明 |
| --- | --- |
| 影像文件夹 | 存放立体/多视像对的文件夹，**要求不存在子文件夹**，支持 `RPB`、`RPC`、`XML` 三种 RFM 格式 |
| 临时文件夹 | 默认 `影像文件夹\Temp` |
| 输出 DSM | 默认 `影像文件夹\dsm\dsm.tif` |
| 输出 LAS | 默认 `影像文件夹\dsm\terrain.las`，可勾选控制；**目前未实现输出 LAS 功能** |
| DOM / DEM / Geoid 路径 | 参考数据，支持本地或 `Online Control Source` 网络获取 |
| 采用平差 | 不勾选时 DOM/DEM/Geoid/考虑 DEM/匹配窗口大小五项灰显 |
| 考虑 DEM | 平差匹配时是否考虑 DEM 进行模型预测，建议勾选 |
| 匹配窗口大小 | 默认 512 |
| 匹配算法 | `SGM_CUDA`、`SGM_GLSL`、`SGM_AVX2`、`SGM_SSE`。使用 CUDA 需 NVIDIA 显卡且驱动最新，否则可能未知错误；条件允许建议 `SGM_CUDA`，仅 CPU 则选 `SGM_AVX2` 或 `SGM_SSE` |
| 投影方式 | `WGS84` 或 `WGS84_UTM` |
| 输出分辨率 | `-1` 或 ≤0 时程序智能计算 |
| 最大视差 | 建议 2 的倍数且不超过 1024，否则显存/内存可能不足；`-1` 为自动计算（不稳定，出现遗漏区域时请手动设置） |
| 补洞大小(像素) | `-1` 为自动计算（不稳定时请手动设置） |
| 分块大小 | `-1` 或 ≤0 时自动选择 |
| 分层 | tSGM 算法分层大小，建议默认 3 |

**后台作业模式（`SurfInput.xml`）**：`ImgFolder`、`TmpFolder`、`DOMPath`、`DEMPath`、`GeoidPath`、`OutDSM`、`OutLAS`、`OutProj`、`OutRes`、`IsAdjust`、`IsFree`、`IsDEM`、`Win`、`Block`、`MaxDis`、`HoleExt`、`Level`、`FunType`、`IsTest`、`IsDelTmp`、`strHostName`、`strPort`、`IsPause`。

> 其中 `IsFree`（是否自由网平差，推荐不勾选、采用带控立体平差）、`IsDEM`、`Win` 仅在 `IsAdjust` 为真时生效；`HoleExt=0` 表示不补洞。

**输出**：带地理编码信息的 DSM 栅格文件。

### 7.8 匀光镶嵌软件（`MosaicProcessUI.exe` / `MosaicProcess.exe`）

对带地理信息的遥感影像进行匀光匀色（兼容地理匀色）、有效区域识别、初始镶嵌线生成、镶嵌线优化、羽化拼接等操作，形成统一完整的大区域镶嵌影像。支持**正射影像、带 RFM 模型 L1 级影像或二者混合**的模式。

> 实际使用中**建议先进行平差和正射操作**再镶嵌。

**输入**：带 RFM 模型的 L1 级数据、已地理编码的 L2/3/4 级数据，或二者混合。测试数据提供 6 种场景：同投影系_同载荷_四景、同投影系_不同载荷_十七景、同投影系_孔洞_分离情况_十六景、RFM模型(RPB)、不同投影系+RFM模型(RPB)、同投影系+RFM模型(RPC)。

**主要界面参数**

| 参数 | 说明 |
| --- | --- |
| 影像文件夹 | 待镶嵌影像文件夹，**要求不存在子文件夹** |
| 临时目录 | 默认 `影像文件夹\Temp` |
| 输出镶嵌影像 | 默认 `影像文件夹\Output\Mosaic.tif` |
| 输出真彩 / 灰度影像 | 默认 `Mosaic_Color8bits.tif` / `Mosaic_Gray8bits.tif`，仅对应勾选后有效 |
| 忽略背景值 | 与影像 NoData 联合判断有效区域，正整数、半角逗号分隔；暂不支持不同波段不一致的背景值 |
| 去边缘像素 | 有效区域提取时向内腐蚀的像素数 |
| 优化尺度 | 镶嵌线优化采用的影像信息尺度：完整 / 高 / 中 / 低，**默认建议选"高"** |
| 匀光匀色 | 是否进行片内匀光（Wallis 滤波）和片间匀色 |
| 基准底图 | 用 Google/ArcGIS 底图自然色做低频替换；底图为真彩色，**仅对 RGB 波段**做低频替换，其他波段仍走匀光匀色流程 |
| RGB 波段 | 真彩影像波段组合（如 `3,2,1`，序号从 1 开始） |
| 灰度波段 | 灰度影像波段序号 |
| 羽化 / 羽化像素 | 是否按距离加权羽化及缓冲区范围 |
| 输出投影 | 跟随工作投影（**默认建议**）、`WGS84`、`WGS84_UTM`（按镶嵌范围最中间位置取 6° 带） |
| 导出真彩 / 导出灰度 | 控制 8bit 影像导出 |
| 输出分辨率 | 跟随工作投影时不激活；`WGS84` 单位为度，`WGS84_UTM` 单位为米 |

**后台作业模式（`MosaicInput.xml`）**

| 字段 | 含义 |
| --- | --- |
| `ImgFolder` | 待镶嵌影像文件夹，不检测子文件夹。程序自动检测工作投影/像元：全输入同 CRS 则用源 CRS + 源像元；全 RPC 则用目标投影 CRS + RFM 原生 GSD；GCP/混合/无 SRS 则回退 `EPSG:4326` |
| `OutFolder` | 存放中间与诊断产物（有效区域、初始/优化镶嵌线、匀光匀色结果、投影归一化结果、匀色参数等），自动创建，默认 `ImgFolder\Temp` |
| `OutMosaic` | 最终镶嵌结果导出路径，默认 `OutFolder/mosaic_feather.tif`，目录不存在自动创建 |
| `OutRgb` / `OutGray` | 8bit 真彩 / 灰度导出路径，仅在对应开关打开时生效 |
| `SeamScale` | 缝线优化抽稀倍率 `dec = 1<<(SeamScale&3)`：`0`=完整(1)、`1`=高(2)、`2`=中(4)、`3`=低(8)，越大越快越粗 |
| `ErodePx` | 有效掩膜向内腐蚀像素数（剔除边缘噪声/锯齿），`0`=不腐蚀 |
| `NoData` | DN 命中列表任一值即判为无效/背景，如 `0,-9999` |
| `DoDodge` | 匀光匀色总开关。`0` 时跳过匀光匀色，直接读原图并用恒等系数（只测几何/缝线/羽化时用） |
| `RefGoogle` | `0`=Wallis 滤波匀光（默认路径）；`1`=用基准底图（Google/ArcGIS 自然色）做低频替换，不生成 gain/off 场 |
| `ProxyHost` / `ProxyPort` | 参考底图抓取代理。非空时经 host:port 访问 Google，失败则自动回退 ArcGIS；为空时直接走 ArcGIS（免代理）。`DoDodge=0` 时该组参数无意义 |
| `RefLowFreqRes` | 低频网格分辨率（度），`0`=自适应 |
| `RefLowFreqFactor` | 自适应因子，低频网格边长 = 源像元尺寸 × 该因子。越小越精细，过小会逼近底图分辨率、引入地物错位伪影 |
| `ExportRgb` / `ExportGray` | 是否导出真彩 / 灰度影像 |
| `RgbBands` / `GrayBand` | 1-based 波段序，按 R,G,B 顺序（`3,2,1` 真彩色）；该顺序同时用于 `RefGoogle` 模式下源 RGB→底图 RGB 的色调映射 |
| `OutputProj` | `WGS84`=`EPSG:4326`；`WGS84_UTM`=按拼接范围中心取最近 6° 带（北纬 326xx / 南纬 327xx）；空=跟随工作投影。该标签优先于内部 targetSrs |
| `OutputRes` | 输出像元尺寸（WGS84 为度、UTM 为米）。>0 作为 targetPixel；空/0=自动 |
| `KeepMosaic` | 是否保留最终镶嵌影像（`0` 则在 8bit 导出后删除），仅当 `ExportRgb/ExportGray` 打开时有效 |
| `WriteWinnerIndex` | 是否导出影像序号索引图，`1` 时额外写 `winner_index.tif`，每像元 = 来源影像索引 `S{v}`（-1=NoData） |
| `FeatherPx` | 羽化过渡单侧宽度（全分辨率像元），默认 60。越大越平缓，越小越接近硬拼 |
| `NoFeather` | `1`=关闭羽化（纯赢家硬拼，诊断用），此时 `FeatherPx` 失效 |
| `NoGapfill` | `1`=关闭"最近有效质心"缝隙填补，`0`=保留（解决亚像元缝隙/伪赢家问题） |
| `IsPause` | 完成后是否暂停。UI 手动运行时写 `1`；**批处理/脚本调用务必设 `0`**，否则进程会一直挂起等待按键 |

**输出**：经过地理编码和多影像匀光镶嵌后的大区域影像文件；勾选导出时会附带 8bit 真彩与灰度图像（对原始镶嵌结果进行灰度值拉伸）。

### 7.9 快速融合软件（`FastFusionUI.exe` / `FastFusion.exe`）

对全色和多/高光谱进行影像融合，提高多/高光谱影像分辨率。兼容**像素比例对应、地理信息对应、RFM 模型对应**三种像素对应方式。不支持无像素对应方式，也不支持混合模式。

**输入**：测试数据提供 3 种情况——`NoGeo`（无地理坐标，按长宽像素比例等比例对应）、`UseGeo`（带投影地理信息）、`UseRFM`（带 RFM 模型，**目前仅采用平均高程对应**，成像角度差异大时可能像素对应失配）。

**界面参数**：全色影像路径、多光谱影像路径、输出影像（默认 `影像文件夹\全色影像_Fusion.tif`），以及语言切换与批处理操作。

**后台作业模式（`FastFusionInput.xml`）**：`PanPath`、`MuxPath`、`OutFile`、`IsPause`。

**输出**：融合影像；若原始全色影像带有地理信息，输出融合影像具有相同地理信息。

### 7.10 快速超分重建软件（`FastSuperResUI.exe` / `FastSuperRes.exe`）

对各级遥感影像进行超分辨率重建、升采样和影像增强操作，支持 **2/3/4/8** 四种倍率，支持带地理信息或 RFM 模型的遥感影像。

**输入**：支持无地理信息、投影地理信息、RFM 模型信息三种方式。测试数据包含 WorldView3（0.5 m，带投影）、GF2（3 m，rpc 格式）、高景多光谱（2 m，rpb 格式）。

**界面参数**

| 参数 | 说明 |
| --- | --- |
| 输入影像 / 输出影像 | 输出默认命名：超分 `输入影像_SR_x倍率.tif`；升采样 `输入影像_BI_x倍率.tif`；增强 `输入影像_EN.tif` |
| 算法 | `影像超分`（超分算法）、`影像升采样`（Cubic 简易插值，用于效果对比）、`影像增强`（保持原始分辨率，增强细节） |
| 倍率 | 支持 2/3/4/8 |

**后台作业模式（`FastSuperResInput.xml`）**：`InputPath`、`OutputPath`（手册正文写作 `OutputFile`，以作业单模板为准）、`Algorithm`（`0` 超分 / `1` 升采样 / `2` 增强）、`Scale`、`IsPause`。

**输出**：超分/升采样/增强后的影像；若影像带地理信息，输出具有相同地理信息。

### 7.11 快速传感器校正软件（`FastSCUI.exe` / `FastSC.exe`）

在**未知 L0 级影像辅助数据信息与定标信息**的情况下，采用影像相关技术对分片分波段的 L0 级原始遥感影像的波段间和 CCD 间进行相关与平差运算，完成**条纹去除、传感器拼接、波段配准与片间匀光**。

> ⚠️ 该软件主要用于**应急数据处理**，不能完全替代严格的预处理流程，不能保证 100% 正确。对长条带、分片积分时间、大畸变、低稳定度、低测量精度等成像与硬件质量较差的情况存在失败可能。

**输入**：分线阵与面阵两类。

- **线阵**：L0 级 tif 影像，按星上默认 CCD 和波段排列，存在 CCD 错位和波段错位。测试数据命名规则为 `硬件拼接模式_硬件质量_中心纬度_中心经度_分辨率`：
  - 硬件拼接模式：光学拼接 / 机械拼接（**算法内部自动判定，不作为输入项**）
  - 硬件质量：高 / 中 / 低（**算法输入项**）。质量差的数据设为"高"会得到错误结果；质量好的数据设为"低"会耗费更多时间且可能不稳定
  - 中心经纬度、分辨率：不作为算法输入项，用于后期快速地理配准
- **面阵**：多帧影像按扫描顺序从上到下/从左到右用递增数字编号，软件自动按编号排序完成拼接。

**界面参数**

| 参数 | 说明 |
| --- | --- |
| 线阵-输入影像 / 输出影像 | 输出默认 `影像文件夹\输入影像_stitch.tif` |
| 线阵-硬件质量 | 高 / 中 / 低，**必须正确指定** |
| 线阵-CCD 数量 | 选取影像后自动智能估计，可手动修改。数据量大时估算阶段界面会假死一段时间 |
| 线阵-基准波段 | 默认取中间波段，建议采用硬件排列上居中的波段以减少波段偏移量 |
| 线阵-条纹去除 | 采用图像处理方式（非精确相对辐射校正）。与影像内容关联大，云/水/单调地物多时效果有限 |
| 线阵-片间匀光 | 消除不同 CCD 间色差，同样为图像处理方式，云/水/单调地物多时效果有限 |
| 线阵-波段配准 | 一般默认勾选；光栅高光谱默认波段已配准，可不勾选以减少计算量并提高可靠性 |
| 面阵-输入文件夹 | L0 级影像文件夹，**不包含子文件夹** |
| 面阵-输出影像 | 默认 `影像文件夹\stitch.tif` |
| 面阵-基准波段 | 同线阵 |
| 面阵-片间匀光 | 消除不同帧之间色差，云/水/角度变化/单调地物多时效果有限 |

**后台作业模式（`FastSCInput.xml`）**

| 字段 | 适用模式 | 含义 |
| --- | --- | --- |
| `Mode` | 线阵+面阵 | `Line` 线阵 / `Plane` 面阵 |
| `InFile` | 线阵 | L0 级遥感影像路径 |
| `InFolder` | 面阵 | L0 级影像文件夹路径（不含子文件夹） |
| `OutFile` | 线阵+面阵 | 输出影像路径 |
| `Type` | 线阵 | 硬件质量（高/中/低） |
| `CCDNum` | 线阵 | CCD 数量 |
| `RefB` | 线阵+面阵 | 基准参考波段 |
| `IsMatchB` | 线阵 | 是否进行波段配准 |
| `IsColor` | 线阵+面阵 | 是否进行片间/帧间匀光 |
| `IsStripe` | 线阵 | 是否进行条纹去除 |
| `IsTest` | 线阵+面阵 | `0` 处理后删除中间数据；`1` 保留 |
| `IsPause` | 线阵+面阵 | 完成后是否暂停 |

**输出**：完成 CCD 拼接、波段配准、色差校正、条纹去除的影像，**不带有任何地理信息，也不具有 RFM 模型**。

### 7.12 快速地理配准软件（`FastGeoRefUI.exe` / `FastGeoRef.exe`）

采用影像相关技术与在线网络控制信息，在无影像详细地理信息和星上辅助数据的情况下，将未知地理信息的遥感影像与在线网络参考控制（或本地参考控制）进行相关操作，进而采用地形相关技术进行 **RFM 模型生成**。

> ⚠️ 目前仍需**已知大概位置与分辨率**（无需位置与分辨率的算法仍在开发中）。主要用于应急数据处理，不能完全替代严格预处理流程，不能保证 100% 正确。

**输入**：两类

1. L0 级数据经快速传感器校正生成的结果，命名规则 `硬件拼接模式_硬件质量_中心纬度_中心经度_分辨率`
2. 已有平台载荷缺失 RFM 模型的 L0 或 L1 级数据，命名规则 `平台名称_中心纬度_中心经度_分辨率`，并附带本地参考控制 `平台名称_载荷名称_DEM.tif` 与 `平台名称_载荷名称_DOM.tif`

> 中心纬度北纬为 N、南纬为 S；中心经度东经为 E、西经为 W。

**界面参数**

| 参数 | 说明 |
| --- | --- |
| 影像路径 | 待配准影像，后随下拉框选择参与配准的波段（从 1 开始） |
| 输出 RFM | 默认 `影像文件夹\输入影像路径_rpc.txt` |
| 输出正射 | 默认 `影像文件夹\输入影像路径_rectify.tif`，复选框控制是否输出 |
| DOM / DEM / Geoid 路径 | 参考数据，支持本地或 `Online Control Source` 网络获取；本地 DOM 时后随下拉框选择配准波段 |
| 初始纬度 / 初始经度 | 输入影像中心大概位置，单位 °，北纬/东经为正值 |
| 分辨率(米) | 输入影像大概分辨率 |
| 算法精度 | 精确 / 中等 / 快速三档，计算量依次递减、精度依次变差。质量好、非长条带、畸变小 → 精确；质量差、长条带、畸变大 → 快速（RFM 拟合精度本身有限） |
| 重采方法 | 默认 `BiCubic_4P` |
| 投影设置 | `WGS84` 或 `WGS84_UTM` |

**后台作业模式（`FastGeoRefInput.xml`）**

| 字段 | 含义 |
| --- | --- |
| `ImgPath` | 待配准遥感影像路径 |
| `RFMPath` / `RectifyPath` | 输出 RFM 模型 / 正射影像路径 |
| `RefMode` | 参考数据源类型：`DOM`（本地参考控制）/ `WMS`（网络参考控制） |
| `DomPath` / `DemPath` / `GeoidPath` | 参考 DOM / DEM / 大地水准面路径 |
| `Lat` / `Lon` / `Res` | 中心大概纬度 / 经度 / 分辨率 |
| `Type` | 算法精度：精确(0) / 中等(1) / 快速(2) |
| `NoL` / `NoR` | 原始影像配准波段号 / 本地参考 DOM 波段号（网络控制时不作用） |
| `MType` | 地理配准算法类型，`0/1/2`，**默认建议 2** |
| `Restype` | 重采样方法 |
| `IsRectify` | `0` 只输出 RFM；`1` 额外输出正射影像 |
| `ProjType` | 输出投影 |
| `StrHostName` / `StrPort` | 代理 IP 与端口（手册正文写作 `strHostName`/`strPort`，以作业单模板为准） |
| `IsTest` | `1` 测试模式（输出中间结果不删除）；`0` 生产模式 |
| `IsPause` | 完成后是否暂停 |

**输出**：采用地形相关技术生成的 RFM 模型；若选择正射，同时输出正射校正影像。

## 8. 预处理配置文件 PreConfig

`PreConfig` 为**影像预处理软件内部使用**的配置文件目录，默认与程序同目录，可通过 `PreProcess.ini` / `GeoParse.ini` 中的 `PRE_CONFIG` 字段指定绝对路径。

### 8.1 文件概述

预处理配置分两类：

- **定标参数**：程序运行所需的几何、辐射及光谱定标参数。
- **算法参数**：算法运行所需的配置参数。

### 8.2 定标参数

**组织方式**：一个平台一个文件夹 → 平台内一个载荷一个文件夹。根目录下的 `GlobalPath.ini` 用于配置 DOM 的 Tiles 路径与 DEM 的 SRTM 路径（备选，平台内 NC 文件未找到路径时采用）。载荷文件夹内的定标参数可直接放置，也可另建多层文件夹分类保存，程序会进行多层目录搜索。

**存储格式**：文本格式或二进制格式，程序自动识别。交付时建议统一存储为二进制格式（使用 GeoPara 的 `ConvertParaFile` / `ConvertParaFileAll` 转化）。

**定标文件扩展名**

| 扩展名 | 类型 |
| --- | --- |
| `ext` | 外定标文件 |
| `cbr` | 内定标文件 |
| `rad` | 相对辐射定标文件 |
| `arad` | 绝对辐射定标文件 |
| `bpd` | 盲元定标文件 |
| `wav` | 标称波长文件 |
| `crw` | 中心实际波长文件 |
| `srf` | 波谱响应曲线文件 |
| `mtf` | MTF 定标文件 |

**五种命名方式**（`Inter` 格式 `%d`，`Gain` 格式 `%0.1f`，`Exposure` 格式 `%0.2f`）：

| 命名方式 | 单波段 | 多波段 |
| --- | --- | --- |
| 独立时间 | `YYYY-MM-DD-HH-MM-SS` | `YYYY-MM-DD-HH-MM-SS-B?` |
| 独立相机参数 | `Inter-Gain-Exposure` | `Inter-Gain-Exposure-B?` |
| 独立积分级数 | `Inter` | `Inter-B?` |
| 时间+相机参数 | `YYYY-MM-DD-HH-MM-SS_Inter-Gain-Exposure` | `YYYY-MM-DD-HH-MM-SS_Inter-Gain-Exposure-B?` |
| 时间+积分级数 | `YYYY-MM-DD-HH-MM-SS_Inter` | `YYYY-MM-DD-HH-MM-SS_Inter-B?` |

搜索时**优先搜索多波段**，不存在带波段序号的文件时再进行单波段搜索（多光谱优先是因为部分多光谱共用参数、无波段配置）。五种命名方式的搜索优先级视具体场景而定。

**各定标文件要点**

- **几何定标**：仅支持独立时间命名。`ext` 一个载荷一个，与波段无关，允许为空（空即单位阵）；发射时设置发射时间，每次调焦需在调焦时间节点设置新的外定标文件；外定标频率可高于内定标，但每个外定标文件都要有配套的一组内定标文件。`cbr` 单/多波段参数相同时用单波段命名，不同时用多波段命名；**不允许为空**，即使为设计值也必须提供。
- **相对/绝对辐射定标**：一定与相机参数相关，必须带相机参数命名。优先"时间+相机参数"，其次"独立相机参数"（优先采用实际场地定标结果）。`rad` 与波段相关，**为辐射校正必须项**——勾选辐射校正但相对辐射定标参数不完整/不存在时程序退出；搜索时同时保存定标景的曝光时间，用于与当前处理景曝光时间形成比例缩放系数。`arad` 与波段相关，为**非必须项**——不完整/不存在/增益值非常接近 1 时不进行绝对辐射校正；绝对辐射校正结果影响最终影像命名（影响 L1A / L1B）。
- **盲元、光谱、MTF 定标**：支持五种命名方式。对积分级数敏感，对增益和曝光相对不敏感。搜索优先级：时间+相机参数 → 时间+积分级数 → 独立相机参数 → 独立积分级数 → 独立时间。
  - `bpd` 与波段相关，非必须；全部不存在则不进行盲元校正，部分存在则对存在盲元的波段进行校正。结果无法从最终产品直接看出。
  - `wav` 与波段无关，非必须；不存在则不进行光谱校正；目前只针对线阵。
  - `crw` 与波段无关，非必须；不存在则不进行光谱校正；目前只针对线阵。
  - `srf` 与波段有关，**不参与运算**，仅用于写元数据。
  - `mtf` 与波段有关；不完整/不存在时不进行 MTFC。

### 8.3 算法参数

支持三种存储方式：**INI 文本 → Json → SQLite**，程序按此顺序逐次搜索，均不存在则存在问题。INI 为基本存储方式。

| 文件 | 位置 | 用途与主要字段 |
| --- | --- | --- |
| `GlobalPath.ini` | `PreConfig\` 根目录 | NC 处理所需的 WMS 瓦片 DOM 与 SRTM30 高程数据绝对文件夹路径 |
| `AP.ini` | `PreConfig\<平台>\` | AP 数据优化匹配算法参数（CCD 与 Mux 分开配置） |
| `UP.ini` | `PreConfig\<平台>\` | 联合处理、融合、面转线配置（见下） |
| `DX.ini` | `PreConfig\<平台>\<载荷>\` | WRS 划分 Path/Row 所需的卫星轨道与相机参数，用于全球编目划分 |
| `model.ini` | `PreConfig\<平台>\<载荷>\` | 成像模型构建及 SC 处理等几何模型参数 |
| `MTF.ini` | `PreConfig\<平台>\<载荷>\` | MTFC 配置参数 |
| `NC.ini` | `PreConfig\<平台>\<载荷>\` | 无控修正处理 NC 配置参数 |
| `RC.ini` | `PreConfig\<平台>\<载荷>\` | 辐射校正配置参数 |
| `RGB.ini` | `PreConfig\<平台>\<载荷>\` | 贝尔重建与缩略图生成配置参数 |

**`UP.ini` 主要字段**

- 总体：`SAT_ID`（加密用平台代号）、`MJD`（平台统一基准时间，共同作用于辅助数据）
- AP 联合操作：`AP_TYPE`（`MUX`/`CCD`/`COMBINE`/`P2L`，为 `NULL` 则不进行 AP）、`AP_CCD`、`AP_MUX`
- 联合处理：`UCA_NUM`（联合处理载荷个数）、`UCA_CAM`（各载荷名称）。联合处理将进行联合编目，再依此处理；一般只对线推扫条带数据进行（只有线推扫才有物理分景、才能在像素级配准对齐）
- 融合处理：`PSH_IS`（是否融合）、`PSH_PAN`（全色载荷名）、`PSH_MUX`（多光谱载荷名）、`PSH_NAME`（融合影像名称）
- 面转线：`P2L_IS`、`P2L_P_NUM`（目前仅支持一个）、`P2L_P`、`P2L_L`（参考线阵载荷）、`P2L_NAME`（虚拟线阵载荷名称）

**`model.ini` 主要字段**：`USE_ORB_POLY`、`USE_ATT_POLY`、`ORB_POLY`、`ATT_POLY`、`SC_ORB_POLY`、`SC_ATT_POLY`、`CCD_NUM`（载荷传感器片数，线阵才有用）、`CAM_TYPE`（`MUX`/`PAN`/`HSI`/`PIM`/`VIM`，使程序不依赖载荷名称判断类型）、`IS_LINEAR`（是否线阵）。

**`NC.ini` 主要字段**：`nc_isnc`、`nc_type`（`0` 相位相关，`1` HOG）、`nc_domfolder`、`nc_demfolder`（为空或 `NULL` 时采用 `GlobalPath.ini` 中的路径）。

**`RC.ini` 要点**：部分分片 CCD 存在片间色差，需用 CCD 片间重叠区域同名点配准进行纠正。另有两个关键字段：
- `rc_bin`：沿轨分时成像像素个数。对 HN1-02 等平台，沿轨四个像素同时成像并以贝尔规则记录，因此物理分景和 SC 等切景操作时沿轨方向需按 `rc_bin` 倍数进行，否则产生错误。
- `rc_tap`：每片 CCD 的抽头个数（抽头间可能产生色差，目前未观察到，也未实现）。

**`RGB.ini` 主要字段**：`RGB_NUM`（缩略图波段数，`1` 灰度 / `3` RGB）、`RGB_INDEX`（缩略图各波段在原始影像上的波段索引序号，从 1 开始）、`RGB_BAYER_IS`、`RGB_BAYER_TYPE`、`RGB_Quant_Bits`。

- 年月日：`20260820` = 2026 年 08 月 20 日（数据接收日期）

```
接收站名称_卫星标识_年月日_时分秒_任务号_分景号_层级_载荷
```
示例：`KS_XJ01_20260820_231200_001_L0_PAN.tif`

- 层级：`L0` = L0 级产品
- 载荷：`PAN` = 全色

### 9.4 L1 级产品命名规范

```
卫星标识_年月日_景ID_Path_Row_中心经度_中心纬度_层级_载荷
```
示例：`XJ01_20260819_0000000001_0210_0778_W99.0_N20.0_L1B_PAN.tif`

- 年月日为**拍摄日期**（非数传日期）
- 景 ID：编目 ID（`0000000001`）
- Path/Row：编目 Path/Row（`0210_0778`）
- 中心经度/纬度：分景后影像中心（`W99.0_N20.0`）
- 层级：`L1B`、`L1BF`（融合）

### 9.5 L2/3/4 级产品命名规范

```
卫星标识_年月日_景ID_Path_Row_中心经度_中心纬度_层级_载荷
```
示例：`XJ01_20260819_0000000005_0210_0782_W99.1_N19.6_L4A_PSH.tif`

### 9.6 控制数据格式（`.gcp`）

控制点文件后缀名为 `gcp`，具有三种形式：

- **控制点形式**：用于几何纠正和几何精度验证（NC、正射纠正、几何精度验证等）
- **同名点形式**：用于存储影像间同名点对信息（AP、融合等），仅利用左右影像的同名点像点坐标
- **检校点形式**：用于存几何检校用的控制点信息（检校操作与定标验证）

**文件结构**（一般情况下所有控制点均在 **WGS84** 基准下）：

| 行 | 内容 |
| --- | --- |
| 第 1 行 | 控制点文件标识（版本号），目前版本已达 `XJ_GCP2.0` |
| 第 2 行 | 控制点个数信息 |
| 第 3 行 | 控制点物方坐标对应投影信息的 WKT 语句 |
| 第 4 行起 | 每个控制点信息 |

**列定义**：

| 列 | 含义 |
| --- | --- |
| 1、2 | 待纠正影像的像点像方坐标 x（垂轨）、y（沿轨）。控制点形式=待纠正影像像点；同名点形式=左影像像点；检校点形式=检校影像像点 |
| 3、4 | 物方平面坐标。WKT 为地理坐标时表示经度、纬度（度）；为投影坐标时表示 x（经度方向）、y（纬度方向）（米） |
| 5 | 物方高程坐标（米） |
| 6、7 | 控制点在控制 DOM 数据上的像点坐标 x（垂轨）、y（沿轨）。控制点/检校点=参考影像像点；同名点=右影像像点 |
| 8 | 控制点形式：类型（`0` 控制点、`1` 检查点、其他无效）；同名点形式：不起作用；检校点形式：检校点在检校影像上的 CCD 片索引号（从 0 开始） |
| 9、10 | 控制 DOM 像点坐标与待纠正影像像点坐标之差 dx（垂轨）、dy（沿轨），相减顺序为**右减左** |

## 10. 标准产品列表

### 10.1 标准 L0 级产品

| 文件名称 | 文件说明 |
| --- | --- |
| `文件名.tif` | 影像文件 |
| `文件名_pre.jpg` | 浏览图 |
| `文件名_ico.jpg` | 拇指图 |
| `文件名（无载荷）.EPH` | 轨道文件 |
| `文件名（无载荷）.ATT` | 姿态文件 |
| `文件名.IT` | 行时文件 |
| `文件名.bands.txt` | 波段信息文件 |
| `文件名.catlog.txt` | 影像范围文件 |
| `文件名.GainInt.txt` | 增益、积分级数、曝光时间文件 |
| `文件名.kml` | 地理范围文件 |
| `文件名.xml` | 元数据文件 |

**辅助数据格式说明**

- **轨道数据文件（`.EPH`）**：一轨一个。第 1 行为时间计时起始历元（UTC）；第 2 行为各列信息；第 3 行为轨道点个数。列：① 轨道点序号；② 轨道点累计秒值；③~⑧ WGS84 下位置与速度（m、m/s）；⑨ 累计秒对应 UTC 时间；⑩ 星下点经度（°）；⑪ 星下点纬度（°）。
- **姿态数据文件（`.ATT`）**：一轨一个。格式同上三行头。列：① 姿态点序号；② 累计秒值；③~⑥ J2000 到本体坐标系的姿态四元数 Q0/Q1/Q2/Q3（J2000→body，文件为数学表达，代码中采用 Q1/Q2/Q3/Q4 工程表达）；⑦ 累计秒对应 UTC 时间；⑧~⑩ 轨道坐标系到本体坐标系的欧拉角 Roll/Pitch/Yaw（°）。经过 AP 和 NC 操作后的姿态文件扩展名分别为 `ap` 和 `nc`，使用顺序为 **nc → ap → att**。
- **行时数据文件（`.IT`）**：一个载荷一组。第 1 行起始历元；第 2 行行时数据起始/中间/结束 UTC 值；第 3 行行时点个数。列：① 行时序号（线推扫为整轨影像行号，从 0 开始；面阵滑动与视频为帧号，从 1 开始）；② 行成像时刻累计秒值；③ 行积分时间秒值（与行成像时刻结合进行跳秒判断）。线推扫若存在分片积分时间，则每片 CCD 均有单独行时文件。
- **切景索引文件（`.catlog.txt`）**：一个载荷一个。线推成像时第一个数字为切景开始行（从 0 开始），第二个为结束行（不含）；面阵成像时为处理开始/结束帧序号（从 0 开始，不含结束帧）。用于自动化流程 SC 指定 L0 处理范围（逻辑分景）。手动流程每次物理分景都对实际影像切景，物理分景后的切景索引文件对应新的切景结果文件。
- **波段索引文件（`.bands.txt`）**：一个载荷一个，告诉程序影像各波段对应的实际相机波段索引序号（从 1 开始）。凡涉及波段序号的定标参数搜索皆以此为准。**多光谱/高光谱为必须文件**，且波段个数须与影像一致；其他数据可不罗列，程序按影像波段序号赋序列值。
- **相机参数文件（`.GainInt.txt`）**：一个载荷一个，三列分别为**增益、积分级数、曝光时间**（曝光时间单位微秒 us）。凡涉及相机参数的定标参数搜索皆以此为准，波段个数须与影像一致。
- **影像格式**：
  - 线阵：`接收站名称_卫星标识_年月日_时分秒_任务号_L0_载荷.tif`，如 `KS_XJ01_20260820_231200_001_L0_PAN.tif`
  - 滑动面阵：`..._L0_载荷_帧号.tif`，帧号 `%05d`，如 `KS_XJ01_20260820_231200_001_L0_PIM_00002.tif`
  - 视频：`..._L0_载荷_帧号.jpg`，帧号 `%05d`，如 `KS_XJ01_20260820_231200_001_L0_VIM_00002.jpg`

## 11. 元数据

**总要求**：元数据文件为采用 **XML 1.0** 描述的纯文本文件，结构上用一个 XML 元素记录一个元数据项，开始/结束标记记录元数据项名称，数据内容记录元数据值（不限定字符数）。元数据项按属性与内容相近程度划分为若干子集并嵌套，构成树形逻辑结构。

**逻辑结构**：元数据文件应包括 **产品文件组成信息、基本信息、生产信息** 3 个部分。

**填写规则**：所列元数据项都应提供并逐项记录，不应有空项。有值时如实记录；**无值时记录为 `empty`**；**值未知时记录为 `unknown`**。需文字说明的数据项应以简洁清晰的语言完整表达。

**各级元数据内容与格式**

| 级别 | 内容分组 |
| --- | --- |
| **L0** | 分景元数据基本信息、分景元数据范围信息 |
| **L1** | 产品组成信息、产品信息、范围信息、相机信息、绝对辐射校正信息、光谱定标信息、光谱响应信息、处理信息 |
| **L2/3/4** | 产品组成信息、产品信息、范围信息、相机信息、绝对辐射校正信息、光谱定标信息、光谱响应信息、处理信息 |

> 各元数据项的完整清单（序号、元数据项、数据类型、值、XML 标记、备注）请参见用户手册附录九中的表 6~表 23。

## 13. 常见问题与注意事项

**通用**

1. **`IsPause` 字段（后台作业单）**：UI 手动运行时写 `1` 便于查看日志；**批处理/脚本调用务必设为 `0`**，否则进程会一直挂起等待按键。
2. **平台/载荷必须填写正确**：影像预处理、数据解析等模块依据平台类型查找配置与定标参数，填写错误会导致程序无法执行甚至崩溃。
3. **试用限制**：试用版保持网络畅通以完成联网试用的验证；内网/无网需申请单机激活码。
4. **`PRE_CONFIG` 配置路径**：`PreProcess.ini` 与 `GeoParse.ini` 中的 `PRE_CONFIG` 字段指向预处理配置目录。**若该路径指向其他机器或开发目录而本机并不存在，需改为本机 `PreConfig` 目录的绝对路径**（如 `.\PreConfig\`），否则预处理/解析会找不到配置与定标参数。
5. **DEM / Geoid 高程系统**：DEM 路径可替换为更高分辨率数据，但**范围必须完全覆盖生产影像范围**，并注意其高程系统；正高系统需补充 Geoid 文件转换为椭球高。
6. **在线控制信息**：使用 `Online Control Source` / `WMS` 时需网络畅通，必要时在 `strHostName` / `strPort`（部分模板为 `StrHostName` / `StrPort`）中配置代理。
7. **内存/显存**：DSM 最大视差过大（>1024）可能导致显存/内存不足；快速传感器校正在大影像上估算 CCD 数量时界面会短暂无响应（假死）。
8. **命令行/作业单字段差异**：用户手册正文中的个别字段名与随软件提供的 XML 模板略有差异（如 `siDeleteTempFile` vs `IsDeleteTempFile`、`OutputFile` vs `OutputPath`、`strHostName` vs `StrHostName`）。**实际调用时以 `XJFastSystem\` 目录下的作业单模板为准**。

**各模块已知限制**
